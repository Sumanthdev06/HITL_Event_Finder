# Human In the Loop Event Finder 

An intelligent, agentic system that helps users find local events, concerts, and sports games while checking the weather for their specific location. This project utilizes a **Human-in-the-Loop** architecture, ensuring that the AI's suggestions are reviewed and approved by a person before being finalized.

---

## Overview

This application is built using a modern AI stack. It leverages **LangGraph** to manage complex state transitions and tool-calling logic, **OpenAI's GPT-4 Turbo** as the reasoning engine, and **Streamlit** for a vibrant, user-friendly frontend.

### Key Features

* **Real-time Event Search:** Integrated with the Tavily Search API to find current local happenings.
* **Weather Forecasts:** Uses the OpenWeatherMap API to provide context on whether the event might be rained out.
* **Human-in-the-Loop:** Every response generated by the agent must be approved or rejected by the user.
* **Feedback Loop:** If a response is rejected, users can provide feedback (e.g., "Only show me indoor events"), and the agent will re-process the request based on that feedback.
* **Vibrant UI:** A custom-styled Streamlit interface with a warm orange theme and "thinking" status updates.

## The Workflow

The project is divided into two main components: the **Agent Logic** and the **User Interface**.

### 1. The Agent Graph (`event_agent.py`)

The logic follows a structured state machine:

1. **Agent Node:** The LLM analyzes the user prompt and decides whether to call a tool or reply.
2. **Conditional Logic:** If tool calls are detected, the graph moves to the `Action` node. If a final response is generated, it moves to `human_approval`.
3. **Action Node:** Executes `search_events` or `get_weather` based on the LLM's request.
4. **Human Approval:** A breakpoint where the graph pauses execution until the user interacts with the UI.

### 2. The Frontend (`app.py`)

* **Thinking State:** While the agent is processing (calling tools or searching), a "Agent's Work in Progress" expander shows the internal steps in real-time.
* **Approval System:** Provides "Approve" and "Reject" buttons. Rejection triggers a feedback form that re-inserts the user's requirements back into the agent's memory.

## Setup and Installation

### 1. Clone the Repository

```bash
git clone https://github.com/Sumanthdev06/HITL_Event_Finder.git
cd HITL_Event_Finder

```

### 2. Set Up a Virtual Environment

```bash
python -m venv venv
source venv/bin/activate  # On Windows use: venv\Scripts\activate
pip install -r requirements.txt

```

### 3. Configure API Keys

Create a `.env` file in the root directory and add your credentials:

```env
OPENAI_API_KEY=your_openai_key_here
TAVILY_API_KEY=your_tavily_key_here
OPENWEATHERMAP_API_KEY=your_openweathermap_key_here

```

### 4. Run the Application

```bash
streamlit run app.py

```

## Usage Instructions

1. **Enter a Query:** Ask about events in a specific city (e.g., "What's happening in New York today?").
2. **Monitor Progress:** Watch the "Agent Thinking" box to see which tools are being triggered.
3. **Review:** Once the agent creates a summary, click **Approve** to save it to chat history or **Reject** to provide feedback and ask for a revision.
